### 2.2 Recommended index on `AUDIT_LOGS_INFM` (volume mitigation)

Because this feature alone will generate one audit row per page mount + per sort click + per bank-popover change, audit reads filtered by this feature should hit an index. If `AUDIT_LOGS_INFM` does not already carry `(WSVC_ID, REG_DTM DESC)` as an index, add it in the Phase 2 backend MR alongside this feature:

```sql
-- V{n+m}__audit_logs_infm_wsvc_id_reg_dtm_index.sql (cross-feature, add if absent)
CREATE INDEX IF NOT EXISTS ix_audit_logs_infm_wsvc_id_reg_dtm
    ON AUDIT_LOGS_INFM (WSVC_ID, REG_DTM DESC);
```

Run `\d audit_logs_infm` against the local DB (or `SELECT indexname FROM pg_indexes WHERE tablename='audit_logs_infm'`) before authoring the migration — the index may already exist from an earlier feature's MR. Idempotency rule applies (`IF NOT EXISTS`).

## 3. Schema gaps — new migrations required

### 3.1 `ACCT_AUTH_INFO` table — new migration

**Filename:** `V{next}__acct_auth_info_for_own_account_transfer.sql`
**Pick `{next}` at MR time** from `wecms-api/src/main/resources/db/migration/` to avoid number collisions (current highest version: check the existing V129/V130/V… range — the migration listing in the migration doc §3 of this feature listed up through V130).

Mirrors legacy DEV's `acct_auth_info` schema column-for-column. The legacy DDL is generated by Jex Studio; the columns referenced by the legacy `ACCT_MSTR_R015` IDO are `BIZ_KEY`, `BANK_CD`, `ACCT_NO`, `USER_ID`, `USE_YN`, `AUTH_TYPE`. Audit + housekeeping columns mirror the `BaseEntity` shape.

```sql
-- =========================================================================
-- V{next}__acct_auth_info_for_own_account_transfer.sql
--
-- Per-(BIZ_KEY, BANK_CD, ACCT_NO, USER_ID, AUTH_TYPE) authority grant table.
-- Used by Own Account Transfer's source-account list to filter the rows a
-- non-admin USER can see, and by the balance-refresh endpoint to defend
-- the patch path against a forged request.
--
-- Legacy: WECMS DEV/WECMS_ETC/xml/service/IDO/IDO.ACCT_MSTR_R015.xml:122-138
-- (the pivot subquery). Refactor mirrors the table column-for-column with
-- a verified `information_schema.columns` query against DEV before commit.
--
-- Idempotent: CREATE TABLE IF NOT EXISTS.
-- =========================================================================
CREATE TABLE IF NOT EXISTS ACCT_AUTH_INFO (
    BIZ_KEY     VARCHAR(20)  NOT NULL,
    BANK_CD     VARCHAR(20)  NOT NULL,
    ACCT_NO     VARCHAR(100) NOT NULL,
    USER_ID     VARCHAR(100) NOT NULL,
    AUTH_TYPE   CHAR(1)      NOT NULL,        -- 'V' (view) | 'W' (withdraw)
    USE_YN      CHAR(1)      NOT NULL DEFAULT 'N',
    REG_ID      VARCHAR(100),
    REG_DTM     VARCHAR(14),
    MOD_ID      VARCHAR(100),
    MOD_DTM     VARCHAR(14),
    CONSTRAINT pk_acct_auth_info PRIMARY KEY (BIZ_KEY, BANK_CD, ACCT_NO, USER_ID, AUTH_TYPE),
    CONSTRAINT ck_acct_auth_info_auth_type CHECK (AUTH_TYPE IN ('V','W')),
    CONSTRAINT ck_acct_auth_info_use_yn    CHECK (USE_YN    IN ('Y','N'))
);

-- The pivot query reads (USER_ID, BIZ_KEY, BANK_CD, ACCT_NO); the PK is the
-- natural index, but a (USER_ID, BIZ_KEY) lookup is also frequent.
CREATE INDEX IF NOT EXISTS ix_acct_auth_info_user_biz
    ON ACCT_AUTH_INFO (USER_ID, BIZ_KEY);
```

Before commit, run the verification query against DEV via the `postgres` MCP (read-only):

```sql
SELECT column_name, data_type, character_maximum_length, is_nullable, column_default
  FROM information_schema.columns
 WHERE table_name = 'acct_auth_info'
 ORDER BY ordinal_position;
```

If DEV's column list diverges (e.g., extra `ETC` columns, different lengths) — update this migration to match before merging. The contacts schema MR uses this same audit pattern (V117 column-type alignment).

## 4. FKs & indexes

### 4.1 Foreign keys

Following the [refactor schema parity rule](../../../../CLAUDE.md) — tenant boundary is enforced **service-layer** via `TenantContext`, not via FK. New FKs only added when legacy schema declares them.

- `ACCT_AUTH_INFO` references the `(BIZ_KEY, BANK_CD, ACCT_NO)` triplet that's `ACCT_MSTR`'s PK — but legacy DEV does **not** declare a FK between them (verified via the legacy IDO using LEFT JOIN, which implies orphan rows are tolerated). Refactor matches: **no FK**.
- `ACCT_AUTH_INFO.USER_ID` references `USER_INFM.USER_ID` — legacy declares no FK. Refactor matches: **no FK**.

### 4.2 Indexes

| Table | Index | Justification |
|---|---|---|
| `ACCT_MSTR` | existing `ix_acct_mstr_biz_ccy (BIZ_KEY, CCY_CD)` from V13 | list query filters by `(BIZ_KEY, CCY_CD='VND', BANK_CD IN (...))` — first two columns hit this index |
| `ACCT_MSTR` | **NEW** `ix_acct_mstr_biz_bank_acct_active (BIZ_KEY, BANK_CD, ACCT_NO) WHERE ACTV_YN='Y'` (partial) | optional optimisation for the list query; defer unless the EXPLAIN ANALYZE on a real-sized seed shows a sequential scan. Phase 2 follow-up, not Phase 1. |
| `ACCT_AUTH_INFO` | PK `(BIZ_KEY, BANK_CD, ACCT_NO, USER_ID, AUTH_TYPE)` | covers the pivot's GROUP BY shape |
| `ACCT_AUTH_INFO` | secondary `ix_acct_auth_info_user_biz (USER_ID, BIZ_KEY)` | the pivot's `WHERE USER_ID = :userId` is the leading predicate; PK leads with `BIZ_KEY` instead, so a USER-keyed index is the better fit |
