## 2. `BUSI_VAS_ACCT_INFM` — full schema (column-for-column with DEV)

DEV column count: **13**. Local schema must match exactly.

| # | Column | Data type | Nullable | Default | Notes |
|---|---|---|---|---|---|
| 1 | `biz_key` | `varchar(20)` | NO | — | tenant scope |
| 2 | `vas_acct_seq_no` | `numeric(10,0)` | NO | — | surrogate per-tenant key |
| 3 | `vas_acct_cd` | `varchar(15)` | NO | — | tenant-unique-while-live |
| 4 | `vas_acct_nm` | `varchar(50)` | YES | — | display name |
| 5 | `vas_acct_enm` | `varchar(50)` | YES | — | English name (optional) |
| 6 | `vas_acct_type` | `char(1)` | NO | — | code `0` Dual / `1` Credit / `2` Debit |
| 7 | `stts` | `char(1)` | NO | — | `A` Active / `I` Inactive |
| 8 | `cont` | `varchar(200)` | YES | — | description / notes |
| 9 | `del_yn` | `char(1)` | NO | `'N'::bpchar` | soft-delete flag |
| 10 | `reg_id` | `varchar(100)` | NO | — | audit |
| 11 | `reg_dtm` | `varchar(14)` | NO | — | `yyyyMMddHHmmss` UTC |
| 12 | `mod_id` | `varchar(100)` | NO | — | audit |
| 13 | `mod_dtm` | `varchar(14)` | NO | — | `yyyyMMddHHmmss` UTC |

### Constraints

- Primary key: `pk_busi_vas_acct_infm (biz_key, vas_acct_seq_no)` — DEV-verified.
- No UNIQUE constraints in DEV. The "duplicate `vas_acct_cd` while live" rule is **enforced in the service layer**, not the DB (legacy parity — DEV allows the same `vas_acct_cd` to appear multiple times when historical rows have `del_yn='Y'`).
- No CHECK constraints in DEV.
- No FOREIGN KEYs in DEV (`busi_vas_acct_infm` is a parent for `acct_mstr.vas_acct_seq_no`, but DEV declares no FK constraint — refactor matches).
- No triggers.

### Indexes (refactor — beyond PK)

| Index | Columns | Purpose |
|---|---|---|
| `pk_busi_vas_acct_infm` | `(biz_key, vas_acct_seq_no)` | PK (DEV-verified) |
| `ix_busi_vas_acct_infm_biz_cd_del` | `(biz_key, vas_acct_cd, del_yn)` | dedup check, list filter |
| `ix_busi_vas_acct_infm_biz_del_stts` | `(biz_key, del_yn, stts)` | Active+Inactive list filter |

Extra performance indexes are allowed by the Legacy Schema Parity Rule even when DEV does not have them.

## 3. Flyway migration plan

> Final numeric `V{N}` slots assigned at MR time. As of 2026-05-11 the next free slot is V75+; the files below are described in their intended order.

### `V{N}__vas_account_schema.sql`

```sql
-- Mirror DEV wecmsvndev.busi_vas_acct_infm column-for-column
-- DEV column count: 13
-- Source verified 2026-05-11 via information_schema.columns

CREATE TABLE IF NOT EXISTS busi_vas_acct_infm (
    biz_key          VARCHAR(20)  NOT NULL,
    vas_acct_seq_no  NUMERIC(10,0) NOT NULL,
    vas_acct_cd      VARCHAR(15)  NOT NULL,
    vas_acct_nm      VARCHAR(50),
    vas_acct_enm     VARCHAR(50),
    vas_acct_type    CHAR(1)      NOT NULL,
    stts             CHAR(1)      NOT NULL,
    cont             VARCHAR(200),
    del_yn           CHAR(1)      NOT NULL DEFAULT 'N',
    reg_id           VARCHAR(100) NOT NULL,
    reg_dtm          VARCHAR(14)  NOT NULL,
    mod_id           VARCHAR(100) NOT NULL,
    mod_dtm          VARCHAR(14)  NOT NULL,
    CONSTRAINT pk_busi_vas_acct_infm PRIMARY KEY (biz_key, vas_acct_seq_no)
);

CREATE INDEX IF NOT EXISTS ix_busi_vas_acct_infm_biz_cd_del
    ON busi_vas_acct_infm (biz_key, vas_acct_cd, del_yn);

CREATE INDEX IF NOT EXISTS ix_busi_vas_acct_infm_biz_del_stts
    ON busi_vas_acct_infm (biz_key, del_yn, stts);

-- Note: refactor does NOT add a wb_get_next_val branch for this table.
-- The vas_acct_seq_no surrogate is generated by VasAcctSeqNoGenerator (Java service).
-- Per DB Function / Legacy Function Policy: prefer Java over PL/pgSQL.
```

Idempotent: `CREATE TABLE IF NOT EXISTS` + `CREATE INDEX IF NOT EXISTS`.

### What this plan does NOT include

- **No new `wb_get_next_val` branch** — the refactor uses `VasAcctSeqNoGenerator` (Java) for surrogate keys, per the DB Function / Legacy Function Policy.

- **No trigger** — DEV has no trigger on this table.
- **No FK to `acct_mstr`** — DEV doesn't declare one; refactor matches.

## 4. Audit columns

`BUSI_VAS_ACCT_INFM` carries the standard four (`reg_id`, `reg_dtm`, `mod_id`, `mod_dtm`). The refactor entity inherits them from `BaseEntity` which already populates them in `@PrePersist` / `@PreUpdate`.

The separate `AUDIT_LOGS_INFM` ledger receives one row per write (see the feature spec §6). No schema change — the existing `wsvc_id varchar(20)` is wide enough for the `vas-account` slug (12 chars). The audit ledger schema below is reference-only — already provisioned by earlier Settings migrations:

| Column | Type | Notes |
|---|---|---|
| `biz_key` | `varchar(20)` | tenant |
| `audit_logs_seq_no` | `numeric` | per-tenant sequence |
| `wsvc_id` | `varchar(20)` | **= `vas-account`** (slug; 2026-05-09 rule) |
| `lang_cd` | `varchar(3)` | from JWT |
| `ref_no` | `varchar(50)` | row anchor (`vas_acct_seq_no` for single-row actions; insert count for Excel) |
| `ref_no1..5` | `varchar(50)` | secondary anchors (`vas_acct_cd`, etc.) |
| `audit_logs_actv` | `varchar(50)` | `CREATE` / `UPDATE` / `DELETE` / `EXCEL_IMPORT_APPEND` / `EXCEL_IMPORT_REPLACE` |
| `audit_logs_actv_dtl` | `text` | JSON snapshot / diff |
| `reg_id` / `reg_nm` / `reg_dtm` | — | who+when |

## 6. Rollback / safety

- Every migration is additive (`IF NOT EXISTS`, `ON CONFLICT DO NOTHING`).
- Local DB rollback = `DROP TABLE IF EXISTS busi_vas_acct_infm CASCADE` + delete the matching `flyway_schema_history` rows. R&D-only; no UAT/PROD path.
- The View Setting seed deletes cleanly via:
  ```sql
  DELETE FROM sys_scr_option_wecms  WHERE web_svc_id = 'vas-account';
  DELETE FROM user_scr_option_wecms WHERE web_svc_id = 'vas-account';
  ```
  (Cleanup script — not a Flyway migration.)
