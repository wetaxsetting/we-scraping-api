# planning/

Sprint plans and long-running task plans for the refactor.

## Purpose

Sprint logs, sprint task plans, multi-feature task plans. One file per sprint or major task.

## What goes here

- Sprint task plans (`task-sprint-N-<topic>.md`)
- Cross-feature task plans (`task-plan-<topic>.md`)
- Sprint retros (if written down)
- Refactor roadmap docs

## What does NOT go here

- Per-feature specs → [../features/](../features/)
- Backend / frontend / DB / migration design → respective subfolders
- Parity audits → [../audits/](../references/audits/)
- Day-to-day TODOs — those live in tickets, not docs

## Example file names

- `task-sprint-0-login-refactor.md`
- `task-sprint-1-backend-golden-chipmunk.md`
- `task-plan-common-backend-functional-seahorse.md`
- `wecms-full-refactoring-roadmap.md`

## Naming

Sprint files: `task-sprint-{N}-{topic}.md`
Task plans: `task-plan-{topic}-{adjective}-{noun}.md` (the adjective-noun suffix is autogenerated by the AI plan tool — keep it for traceability)

## Reference

JEX is **read-only reference**. Sprint plans cite JEX features being translated but never modify JEX docs.
