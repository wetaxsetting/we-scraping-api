| **OQ-VAT-4** | OQ-DB | `EINV_TAX_DETL.EINV_TAXRATE` stored vocabulary must be inventoried from DEV data (e.g. `"10%"` vs `"10"` vs `"KCT"`) before the rate→indicator mapping can be coded. Also: allocation rule for `CT32A`/`CT33A` (out-of-scope revenue) is undefined in the PO package. | **Closed 2026-07-29.** Vocabulary inventoried from DEV: `EINV_TAXRATE ∈ {'0%','5%','8%','10%','KCT','KKKNT'}` (+ null). Mapping coded in `VatDeclarationService.sync` per the Business-Rules table: purchases → `[23]`/`[24]` (all rates); sales `0%→[29]`, `5%→[30]/[31]`, `8%+10%→[32]/[33]`, `KCT→[26]`, **`KKKNT→[32a]`** ("không kê khai nộp thuế" = out-of-scope revenue). `CT33A` not populated by sync (no source rate maps to it in the current data; revisit if a real out-of-scope-VAT case appears). Only the 9 invoice-source cells are overwritten; `[22]` + manual adjustments preserved. |
